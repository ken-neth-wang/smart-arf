Smart-ARF — user / clinic management · system design

Relationships between screens, client state, data layer, edge functions and the database (with RLS). Companion to docs/user-clinic-management-plan.md.

2 · Data model

Memberships are the single source of truth for access; record attribution is historical fact and never rewritten.

3 · Permission tiers & lifecycles

Account state (global) is orthogonal to memberships (per clinic).

flowchart TD
  PA["★ Platform admin — profiles.platform_admin (seeded, rare)
create clinics · deactivate any account · everything below"]
  CA["Clinic admin — membership role 'admin' AT a clinic
approve into OWN clinics · memberships at OWN clinics
allowlist/invite for OWN clinics · restore deleted visits
edit referred-in patients at OWN clinics"]
  HW["Health worker — member of >=1 clinic
see own-clinic + referred-in patients · edit at own clinic · refer out"]
  PA --> CA --> HW

  ACT["acting clinic (header picker) →
new-patient clinic · encounter/photo/audio attribution · records filter"]
  HW -.-> ACT
